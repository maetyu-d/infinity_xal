# Xalaria inspection and integration

Inspected on 10 November 2026. The root hostname failed to resolve in this environment; https://www.xalaria.com/ worked.

The public explorer's data loader reads data/index.json and region files named r-X-Y.json. Its export is described as the universe produced by the game's own deployment exporter. The star index identifies a 200 by 200 logical grid, 20-cell regions and snapshot 5923cc4f. All 7,710 indexed stars were matched to records across 82 occupied regions. The region trees contain 48,081 planets and moons.

Retained facts include source IDs, names, spectral class, technology, directed wormhole edges, life categories, radii, parent distances, periods, orbital tilt, temperature, composition, community/station counts, cloud descriptors and ring bounds. Narrative descriptions were omitted. SHA-256 hashes for the retrieved index and every region are in data/provenance.json.

The TSV data is a compact native snapshot. S rows hold stars and outbound edges; W rows hold worlds and moon primary IDs. Distances use metres and periods use seconds. The original world periods are milliseconds. The source explorer's scale resolves to 10^15 metres per logical grid cell.

Integration preserves Infinity's canonical address and seeded object identity so its asynchronous caches and physics agree. The public source star ID is the Infinity system ID. Primaries retain their ordinal; moons use Infinity's existing primary-plus-ordinal encoding. Map selection, route planning, navigation and rendering share these addresses.

Route planning uses directed breadth-first search. Geometry is never used to invent an edge. The new flight handoff recognises the ancestor system when the selected destination is a world in another system. Infinity then moves the same ship through its normal guided warp and destination reveal.

The map suppresses long wraparound lines in the full-grid view, matching the source explorer's presentation; those edges remain available to the route planner. World radii, temperatures, composition and ring limits remain source facts. Detailed surfaces, cloud appearance, lighting and other scenery are generated by Infinity.

The spatial export does not expose the multiplayer server, accounts, economy, culture/robot simulation, live player construction or city layouts. The spatial export alone cannot reconstruct them. Version 0.3 independently implements the public handbook’s trading and production rules as an offline economy; docs/ECONOMY.md distinguishes source rules from local balance and remaining omissions. README.md records the other model and platform limits.

## Navigation integration update

Version 0.2 separates the preview selection from a committed journey. The destination world and route are retained by XalariaNavigation; the UI can browse other systems without changing them. Checkpoints validate the catalogue fingerprint and every directed edge before restoring the journey.

The same layout supplies drawing and hit testing. Galaxy, orbital and cockpit views share the selected object, active destination and live position. Converting the ship position into the galaxy includes the current render scale; this avoids marker jumps when Infinity changes its reference frame.

The orbital chart deliberately compresses orbital distances for readability and labels itself a schematic. Numerical distances, world identity, target bearing and flight remain engine-derived. Pause/resume, explicit cancellation and manual steering are handled by the journey controller.


## Economy integration update

Version 0.3 adds XalariaEconomy, a persistent C++ ledger for markets, cargo, services, mining, charters and holdings. Trade authorisation uses the physical ship: an orbital market requires a completed docking clamp at its own source-counted port, while a city Exchange requires landing on the same world. Catalogue NPC station counts create the actual docking bodies; completed player stations and vaults add their own berths.

Quotes include the spread, fees and stock impact across the full requested quantity. A transaction validates access, quantity, inventory, capacity and funds before moving cargo or credits. Sealed parcels and authentic artwork participate in hold capacity. The journey controller reserves fuel per leg, charges increasing progress only and persists the charge through pause/resume. Cargo mass feeds Infinity’s existing ship dynamics.

Daily settlement is deterministic by holding and day, so one offline catch-up and equivalent daily updates yield the same outcome. Income stays in tills until physically collected. Deadlines, farm fires, raids and cultural income continue; the ship does not advance while closed. The atomic session checkpoint includes the route, flight, economy and retained berth together. The pre-economy save format migrates on first successful save.
